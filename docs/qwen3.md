# Qwen3-4B-Base support

Qwen3 is an additional benchmark target. Existing Falcon fixtures and the historical
[Milestone 0 validation results](validation/milestone-0.md) are retained.

## Pinned checkpoint and metadata

- Model: [Qwen/Qwen3-4B-Base](https://huggingface.co/Qwen/Qwen3-4B-Base)
- Revision: `906bfd4b4dc7f14ee4320094d8b41684abff8539`
- Architecture: `qwen3.v1`, dense decoder with 36 layers and tied token embeddings.
- Hidden size 2560; 32 query heads and 8 KV heads, each of dimension 128.
- Query projection width 4096, independent of the residual width 2560.
- Per-head learned Q/K RMSNorm, applied before unscaled RoPE; theta 1,000,000.
- Base checkpoint context length 32,768; EOS token 151643.
- Three BF16 Safetensors shards; 398 tensors; **8,044,936,192 payload bytes**.

Configuration and index fixtures were downloaded from the pinned revision on
2026-09-05. Tensor shapes and dtypes were independently read from all three actual
Safetensors headers using HTTP range requests. The index advertises 8,045,591,552
bytes, which is 655,360 bytes more than the actual tensor ranges. Preparation derives
storage from the headers and does not trust that summary field. Full weight payloads
were not downloaded or hashed in this validation.

The pinned metadata is in `tests/fixtures/qwen3/`. Tests reconstruct sparse files with
matching shapes and shard ownership; their zero payloads are never inference weights.

## Implementation

Preparation chooses the adapter from `model_type`. The Qwen3 adapter shares dense
Llama tensor classification and shape validation, adds required per-head `q_norm` and
`k_norm` tensors, and emits `qwen3.v1` plus the `qk_norm` feature flag. Existing manifest
and protobuf fields represent the architecture without a schema change. Wire roundtrip
coverage includes the Qwen manifest. The adapter rejects MoE, bias, scaled RoPE,
sliding-window attention, and odd RoPE head dimensions.

The CPU `LlamaConfig` and layer functions are shared by these two dense decoder families.
Set `query_key_norm=true` and provide `LayerWeights.query_norm` and `key_norm` for Qwen3.
Each learned normalization vector has `head_dimension` elements and is shared across
heads. Q/K projection outputs are normalized per head before RoPE. Attention produces
`attention_heads * head_dimension` values before the output projection restores the
residual width. Llama defaults retain normalization disabled. Invalid normalization
weights and mismatched cache head geometry are rejected before cache mutation.

The control service advertises both architectures and accepts Qwen stage metadata
under the same validation-only load contract. It still does not construct executable
stages or implement execution RPCs. The example MLX/CUDA profiles declare target
architecture support for planning, not measured backend execution support.

## Numerical validation

`tiny-reference.json` is generated by Torch 2.7.1 and Transformers 4.51.3 using eager
CPU float32 attention. A deterministic two-layer Qwen3 model uses hidden width 6,
query width 16, four query heads, two KV heads, and nonuniform learned Q/K norm weights.
The fixture stores all weights, input embeddings, layer outputs, KV contents, and
logits. Native tests compare all these outputs at absolute tolerance `2e-5`, both for
five-token prefill and for three-token prefill followed by two single-token decode steps.
Final logits use the tied embedding as the LM head.

Regenerate the oracle independently of the project's normal dependencies:

```bash
uv run --script scripts/generate_qwen3_reference.py
```

Normal native tests read the checked-in fixture and need neither Torch nor Transformers.
The existing Llama numerical tests remain in the same suite.

## Placement exercise

Running prepare, plan, and explain against a sparse reconstruction of the pinned headers
and the existing interactive workload enumerated **70 candidates**, rejecting 48.
The feasibility estimate selected:

| Worker | Layers | Estimated memory | Usable budget |
| --- | --- | --- | --- |
| Mac M3 Pro | [0, 25) | 9.84 GiB | 12.20 GiB |
| RTX 3060 Ti | [25, 36) | 5.05 GiB | 6.45 GiB |

The reverse order at split 11 ties this score. Accounting includes the per-layer Q/K
norms and a second copy of the tied embedding at the final stage. These are configured
memory estimates, not measured throughput or proof of full-checkpoint execution.
Use the README commands with a real pinned local checkpoint; Qwen output filenames
are separate from Falcon artifacts.

## Validation status and next steps

All 34 Python tests, 32 normal native tests, Ruff, Pyright, and protobuf reproducibility
checks passed. The prepare/plan/explain CLI flow passed on the sparse header fixture.
The existing Apple AddressSanitizer startup issue from the quality review remains an
unresolved toolchain limitation; this change does not claim sanitizer validation.

Next, connect executable stage loading and execution RPCs, then compare the full pinned
checkpoint against Transformers and the MLX/CUDA implementations. Measure actual
memory, TTFT, and decode latency before promoting placement estimates to benchmark results.
